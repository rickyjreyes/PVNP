# PVNP Lean formalization dashboard

A static page that accounts for every manuscript claim against its kernel-checked Lean
counterpart. Open `index.html` in a browser from a clone; it needs no server and makes no
network requests. The repository is private and GitHub Pages is not enabled, so there is no
public deployment.

The percentages count manuscript statements whose exact form is kernel-checked. They do not
measure progress toward proving P ≠ NP. The central theorem, `CrossingSAT.SATLowerBound`, is
unproved, and the page assigns no percentage to it.

## Sources

| File | Role |
|---|---|
| `pvnp/proofs/manuscript-lean-inventory.md` | Authoritative claim statuses. Every total on the page is recomputed from its 91 claim rows and must match its coverage table. |
| The same file at commit `eaf8fa0` (read with `git show`) | The original October 27 statements: 70 Exact, 2 Restricted, 11 Refuted, 8 Open. |
| `results.json` | Curated registry: provenance of the seven amended statements, notes on conditional Exact claims, the Phase X supporting results, the PR #49 experiment, open obligations and exact-head CI evidence. It holds no claim totals. |
| `lean/PVNP/**/*.lean`, `lean/audit/AxiomAudit.lean` | Declaration links (file and line) and axiom-audit membership. |
| `data.js` | Generated by `build.js` from the files above. Do not edit it by hand. |

`index.html` and `app.js` render `data.js`. `inventory.js` parses the inventory.

## Regenerate and check

Run these from the repository root, in a checkout with full git history:

```sh
node pvnp/dashboard/build.js          # write data.js
node pvnp/dashboard/build.js --check  # fail if data.js is stale
node pvnp/dashboard/check.js          # totals, statuses, provenance, links, guards
```

The `PVNP formalization dashboard consistency` workflow runs all three on every change to this
directory or to the inventory.

`build.js` refuses to generate data in any of these cases:

* the coverage table disagrees with the claim rows, in either snapshot;
* the status changes since `eaf8fa0` differ from the amendments registered in `results.json`;
* a retained counterexample is missing from its row or from the Lean sources;
* an Exact row whose wording mentions a premise, hypothesis or implication is neither annotated
  as conditional nor exempted with a reason;
* a supporting result is missing or absent from the axiom audit;
* the PR #49 file appears on the current branch while the registry still lists it as pending.

## Updating after new results

* **Inventory change.** Edit the inventory, then run `build.js`. If a status changes, record the
  change and its PR in `results.json`. An amendment, for example, goes in `amendments`.
* **New Lean result on main.** After the Lean workflow passes on main, update
  `verification.main` (commit, `git rev-parse <commit>:lean`, run ID, completion time). Add the
  result to `supporting` with its PR and exact-head checks, then regenerate. A supporting
  result never changes the 91-claim coverage.
* A proof of the same manuscript statement goes in `formalizations` with its audited declaration and previous status. The II-10 record must retain the corrected empty-input boundary `c·max(n,1)^k` and its external verification provenance, distinct from prior successful hosted-main CI. The finite toroidal module from PR #49 was integrated in #55.

Declaration links are pinned to the verified commit only while `lean/` is identical to it.
Otherwise they point to `main`, and the page warns that newer Lean code is not yet recorded as
verified.
